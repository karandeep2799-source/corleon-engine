# Corleon AI Business OS\n\n## Preview scope\n\nThe first UI slice is available at `/business`. It includes responsive workspace navigation for Overview, AI Command, CRM, Finance, Automations, AI Agents, and Governance; theme switching; local lead entry; searchable lead preview; owner-approval queue interactions; and clear preview-only notices.\n\n## Safety boundary\n\nThis initial slice is a UI preview only. It uses illustrative sample data and browser-local component state. It does not authenticate users, persist records, execute AI tools, send messages, create real invoices, connect payment providers, or execute financial transactions. Approval buttons only dismiss preview queue items and do not authorize or execute external actions. Do not use this preview as a production system of record.\n\n## Production completion gates\n\n1. Implement and test authenticated sessions and server-side organization membership checks before exposing business data.\n2. Extend Prisma with organization-scoped CRM, ledger, invoice, approval, workflow, agent, and audit models. Store all monetary amounts as integer paise (`BigInt` or validated safe integer); never use floating point.\n3. Add migrations and transactional service-layer operations with idempotency keys. Preserve existing models and API contracts.\n4. Implement RBAC, CSRF protections where applicable, input validation, rate limiting, structured logs, and verified audit events.\n5. Add provider adapters for OpenAI, Gemini, and Claude with secrets only in server-side environment storage; begin in mock mode.\n6. Implement workflow scheduling, retry policies, dead-letter handling, and execution logs.\n7. Implement payment provider adapters in test/mock mode; require owner approval and explicit confirmation for every financial or irreversible action. Never store card data or payment credentials.\n8. Add automated unit, integration, authorization, and end-to-end tests; data export and verified account deletion.\n9. Verify preview build, routes, mobile layout, accessibility, database migrations, and health checks before production promotion.\n\n## Local development\n\nUse the repository root commands documented in the root README. The application is part of the existing `apps/web` Next.js workspace.\n
